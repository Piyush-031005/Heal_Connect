Session Management Architecture

This document outlines how user sessions and authentication are managed securely across the Heal Connect web application.

1. Dual-Token System (JWT)

Heal Connect uses JSON Web Tokens (JWT) for stateless authentication. To balance security and user convenience, we use a two-token strategy:

  • Access Token

    Used to authorize API requests. It has a short lifespan of 15 minutes. If stolen, the window of vulnerability is very small.

  • Refresh Token

    Used to request new Access Tokens without prompting the user to log in again. It has a longer lifespan of 7 days.

2. Token Storage

Both tokens are stored securely in the browser's localStorage.

  • hc_access - Stores the user's Access Token.
  • hc_refresh - Stores the user's Refresh Token.

3. Session Lifecycle (What happens when a user leaves and returns?)

Scenario A: Returning within 15 minutes

The hc_access token is still valid. The user accesses the app immediately without any background token renewal.

Scenario B: Returning after 15 minutes, but before 7 days

The Access Token has expired. When the app makes an API request, the server returns a 401 (Unauthorized). The frontend immediately uses the valid Refresh Token to ask the server for a new Access Token, replacing it in localStorage. The user stays logged in seamlessly without noticing.

Scenario C: Returning after 7 days of inactivity

The Refresh Token has completely expired. The system can no longer generate new Access Tokens. The user is logged out automatically, localStorage is cleared, and they are redirected to the Login page.

4. Refresh Token Rotation (Security Feature)

To prevent token hijacking and replay attacks, Heal Connect implements Refresh Token Rotation.

  • Every time the client uses a Refresh Token to get a new Access Token, the server immediately revokes the old Refresh Token in the database.
  • A completely new Refresh Token is generated and returned alongside the new Access Token. This essentially "resets" your 7-day inactivity timer. If you return on day 6, you get a new Refresh Token valid for 7 more days from that moment.
  • If a malicious actor steals a Refresh Token and tries to use an already-revoked token, the system can detect the breach and invalidate the entire token family, requiring the user to re-authenticate.

5. Forced Session Termination (Logout)

If the user explicitly clicks "Logout", both the Access and Refresh tokens are deleted from the local storage, and the backend invalidates them immediately. The session ends instantly regardless of the token expiration times.
