2. End-to-End Operational Flow

Sequence diagram outlining the lifecycle of a wallet recharge followed by a consultation session.

sequenceDiagram participant User as User (App) participant Expert as Practitioner participant API as Node.js API participant WS as Socket.io participant DB as PostgreSQL participant Agora as Agora RTC participant Stripe as Stripe Note over User, Stripe: Phase 1: Wallet Funding User->>API: POST /api/wallet/recharge (Amount) API->>Stripe: Generate Checkout Session Stripe-->>API: Returns Session URL API-->>User: 200 OK (Checkout URL) User->>Stripe: Completes Payment Flow Stripe->>API: Webhook (checkout.session.completed) API->>DB: Increment Wallet Balance API->>WS: Emit 'wallet_updated' WS-->>User: Balance Update Received Note over User, Expert: Phase 2: Consultation Initiation User->>API: POST /api/sessions/initiate (ExpertID) API->>DB: Verify Balance & Create Session API->>WS: Emit 'incoming_call' WS-->>Expert: Receives Notification Expert->>API: POST /api/sessions/accept (SessionID) API->>Agora: Generate Secure RTC Tokens API->>DB: Update Session Status API-->>Expert: Return Agora Token API->>WS: Emit 'call_accepted' (Token) WS-->>User: Receives Token Note over User, Agora: Phase 3: Active Session User->>Agora: Connect & Publish Stream Expert->>Agora: Connect & Publish Stream Agora-->>User: Route Remote Media Agora-->>Expert: Route Remote Media Note over User, DB: Phase 4: Resolution & Billing Expert->>API: POST /api/sessions/end API->>DB: Calculate duration & Deduct Wallet API->>DB: Mark Session COMPLETED API->>WS: Emit 'call_ended' WS-->>User: Terminate Call UI WS-->>Expert: Terminate Call UI
